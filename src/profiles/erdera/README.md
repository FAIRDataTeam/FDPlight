# ERDERA profile

The resource definitions and SHACL shapes with which ERDERA configures the FAIR
Data Point reference implementation for the EJP RD / ERDERA Virtual Platform:
[ERDERA/FDP-Reference-Implementation-Configuration](https://github.com/ERDERA/FDP-Reference-Implementation-Configuration),
commit 4444c1a (2025-05-02), CC0 (`source/LICENSE`).

- `source/` — ERDERA's SHACL files as published (`*.shacl` renamed `.ttl`).
- `shapes/` — generated by `scripts/build-erdera-profile.ts`: for each type,
  ERDERA's Resource shape plus the type's own shape, as the RI's
  `/{prefix}/spec` serves them (every ERDERA schema extends Resource). The root
  takes the FAIR Data Point shapes of the default profile, without Data Service.
- `types.json` — the resource definitions, from the screenshots and text of
  that repository's README (URL prefixes, child relations, list titles).

Changes to ERDERA's shapes, all made by the generator:

1. `dataset` and `distribution` are not valid Turtle at that commit (and since
   April 2025): `] , sh:property [` becomes `] ; sh:property [`, and one
   `sh:name` in `dataset` gets its missing `;` (decided 2026-10-23).
2. `ejp:vpConnection` accepts `ejp:VPDiscoverable` as well as
   `ejp:VPInvisible`, because the profile writes `ejp:VPDiscoverable` unless a
   record is hidden (SPEC §8.4).
3. `dct:type` of a data service is required (`sh:minCount 1`), because the
   VP's Level 2 query lists data services only with one (SPEC §8.6, decided
   2026-10-23).

Checked against the Virtual Platform's Level 1 and Level 2 queries
(`vp-queries/`, SPEC §9.6): every type is listed. Data services are listed by
Level 2 only with a `dct:type` ("Ontological Type of your service"), which
ERDERA's shape leaves optional and this profile requires (change 3). Because
of how the queries filter, one record marked `ejp:VPInvisible` hides every
result of the graph they run on; the app warns when a record is hidden.

Note: ERDERA's dataset shape requires `healthdcatap:hdab` to be
`<http://example.org/hdab/national-health-authority-de>` (`sh:hasValue`, "Germany
is selected as an example default"), so every dataset needs that value.
